# SCG, THE COMMAND LINE TOOL

`scg` takes one scenario json and does one of three things with it. The modes are
mutually exclusive.

| mode | arguments | what happens |
|---|---|---|
| `-r`, `--record` | scenario json, output directory | the signal is generated and written to iq files |
| `-p`, `--playback` | a directory written by `-r` | those files are transmitted |
| `-s`, `--stream` | scenario json | generated and transmitted at once, nothing is saved |

`--help` and `--version` work as usual.

Record the scenario described by `test-3.json` into `recording_test`:

~~~bat
scg.exe -r ..\assets\scenario\test-3.json recording_test
~~~

Play that recording back:

~~~bat
scg.exe -p recording_test
~~~

Stream the scenario, generating and transmitting without saving:

~~~bat
scg.exe -s ..\assets\scenario\test-3.json
~~~

Streaming asks the machine to generate in real time, recording does not, so a scenario
too heavy to stream can still be recorded and played back.

A recording is the duration times the sample rate, so it grows quickly: the sisi rids
under `assets/rid` run at 1.92 megasamples a second, and ten seconds of two channels is
three hundred megabytes.

`scglint scenario <path>` parses and validates a scenario without running anything.

## Gnss spoofing

A `GnssSpoofing` signal is generated by the ssp engine while the scenario plays, with one
thread. Streaming it to a file output runs as fast as the engine goes, which is how to
measure whether a signal can be generated live.

~~~json
{
    "name": "spoof",
    "type": "GnssSpoofing",
    "signal": "GPS_L1CA",
    "startTime": "2026-10-14T12:00:00Z",
    "ephemerisFile": "../assets/rinex/BRDC00IGS_R_20211700000_01D_MN.rnx",
    "trajectory": [
        { "t": 0.0, "latitude": 47.4927, "longitude": 19.0158, "altitude": 120.0 },
        { "t": 60.0, "latitude": 47.4937, "longitude": 19.0168, "altitude": 120.0 }
    ]
}
~~~

| key | what it is |
|---|---|
| `signal` | `GPS_L1CA`, `GPS_L2C`, `GPS_L5`, `GAL_E1`, `GAL_E6`, `GAL_E5b`, `GAL_E5`, `GAL_E5a`, `BDS_B1C`, `BDS_B1I`, `BDS_B3I`, `BDS_B2I`, `BDS_B2a`, `GLO_G1` or `GLO_G2` |
| `startTime` | utc time of the first sample, the satellites are placed for it |
| `ephemerisFile` | rinex navigation file, its ephemerides are moved to `startTime` |
| `trajectory` | `t` in seconds from the first sample, latitude and longitude in degrees, altitude in meters |

The first waypoint is at `t` 0, and after the last one the position holds until the event
ends. Each event plays the signal from its own start, beginning at `startTime`. The event's `frequency` is where the signal lands, its
baseband is centered on the nominal center of `signal`. The output sample rate has to be
whole khz.

A `Zero` signal has no parameters and is silence.
